# 事件降噪方案：diag 存活窗口 + edit 停实时上报（待实施）

> 状态：**方案已定稿，未实施**（2026-10-28 定稿，用户择机实施）。
> 背景：2026-10-27 晚公网服务器过载事故（见 `../reports/2026-10-27-public-server-overload-incident-postmortem.md`），复盘期间发现 diag 事件存在大量打字中间态误报（如敲下 `def` 尚未写函数名时 Pylance 立即报「Expected name after 'def'」），经讨论定稿本方案后暂停实施。

## 目标

1. 消除 diag 打字中间态误报（教师告警条条可信，学生不再虚假变黄）
2. 大幅降低实时上报流量（当晚实测 8,692 条/5h → 目标数百条，-90%+）
3. 不丢数据：L1 本地记录与归档通道保持完整（第二阶段画像数据链不断）

## 方案一：diag 存活窗口（重写 diagnosticsListener.ts）

### 现状问题

`src/events/diagnosticsListener.ts` 当前逻辑：`onDidChangeDiagnostics` → 去抖 1500ms → flush 上报（按错误数量去重）。

两个缺陷：
- 新手敲完 `def` 停顿想函数名（>1.5s 很常见）→ 瞬态语法错误被当真实错误上报
- `lastState` 仅按错误**数量**去重，`def` → `def foo` → `def foo(` 数量变化一路上报

已被否决的替代方案：**保存门控**（保存后才采诊断）——学生一般不手动保存（门控后 diag 几乎不触发），开自动保存又退化回实时误报。两个方向都不干净，弃用。

### 目标设计：错误存活窗口

核心思想：瞬态误报和真卡住的本质区别是**错误存活时长**（打字中间态存活几秒，真卡住持续到解开为止）。不看保存，看错误是否还活着。

```
onDidChangeDiagnostics → 更新各文件当前诊断快照（不直接上报）
每文件每 30s 对账一次：
  - 错误指纹（消息 + 行号范围）首次出现 → 记 firstSeenAt，进入观察期
  - 对账时错误仍存在 且 firstSeenAt 距今 ≥ 30s 且 未报过 → 上报一次，标记 reported
  - 对账时错误已消失 → 丢弃（打字噪音），清除 firstSeenAt；已报过的清除 reported 标记
  - 已报过的错误消失后再出现 → 视为新错误，可再次上报
```

实现要点：
- 指纹 = `message + 起始行:列`，同文件内用 Map 维护 `指纹 → {firstSeenAt, reported}`
- 对账定时器按文件惰性启动（有未决观察项才跑），dispose 时清理全部 timer/Map
- 上报内容沿用现有结构：`{file, errors, warnings, samples}`（samples 取存活错误的 message 前 5 条）
- `lastState` 数量去重逻辑可移除（存活窗口已含去重语义）
- 存活阈值 `30_000ms` 定义为常量即可，暂不做配置项（避免过度设计）

### 行为变化

| 场景 | 现状 | 改后 |
|---|---|---|
| `def` 敲一半停顿 5s | 误报 | 错误存活 5s < 30s，**永不报** |
| 真卡住（错误持续 2 分钟） | 误报+重复多条 | 首次出现 30s 后报 **1 次**，消失后再现才再报 |
| 自动保存开着 | 实时误报刷屏 | 不受影响（判断依据是错误存活，不是保存动作） |
| 学生不手动保存 | 误报照旧 | 不受影响（同上） |
| 真错误上大屏延迟 | ~1.5s | **~30s**（教师视角可接受的代价） |

## 方案二：edit 停实时上报（改 L1 实时上报通道）

### 内容

- 客户端**实时上报白名单排除 `edit`**（仅此一处改动；reporter 现状为所有 surface 原样平铺上报）
- **本地 L1 记录照旧**（jsonl 照写）、归档兜底照旧——画像数据链不断，这是与「彻底删除」的本质区别（彻底删除不可逆，已否决）
- diag/run/behavior/debug 实时上报保持不变（diag 另受方案一存活窗口约束）

### 效果

实时上报量：8,692 条/5h（edit 73% + diag 误报大头）→ run + behavior + 存活窗口 diag ≈ **数百条/晚**。大屏影响：写代码过程中不再边沿推送快照（刷新节奏变为保存/run/心跳 sweep），三值状态判定与在线点亮完全不受影响（登录态模型下 online 靠心跳、状态靠错误事件，代码依据 `aggregator.ts` computeScore/isStudentOnline）。
