# 单文件多任务完成度 + 大屏焦点选择设计

- 日期：2026-11-09
- 状态：已评审（用户拍板：题面注释头声明任务 / 大屏卡内下拉选文件+涌现兜底 / 大桶+任务切换 / 多文件作业本轮不做）
- 关联：`exerciseProgress.ts`（决策 #18 涌现口径）、reviewService、`docs/superpowers/specs/2026-11-04-tech-theme-charts-design.md`

## 1. 背景与问题

现状作业完成度以**文件**为最小粒度（filePath → 学生 → 状态）。实际教学存在两类未覆盖场景：

1. **单文件多任务**：一个 .py 内含任务一/二/三（如 L21 `main_four_imports.py` 的 TODO 1~4）。学生只写完任务一时，整文件评审 fail，任务一的完成被淹没；教师无法按任务粒度看完成度。
2. **焦点漂移**：大屏水桶自动锁定"全局最新涌现题"，学生写得快时焦点自己跳，教师还在讲前一个文件页面就切走了。

## 2. 目标与非目标

**目标**

- 教师在题面注释里声明任务清单 → LLM 逐任务评审 → 每任务一个独立完成度桶（任务二 fail 不影响任务一 pass）
- 大屏完成度卡：文件下拉（默认自动跟随涌现）+ 任务 tab（≥2 任务才显示），教师全程手动掌控焦点
- 学生端扩展零改动、存量题目零迁移零回归

**非目标（明确不做）**

- 多文件作业聚合（知识点02 式目录 → 作业）：`filePath` 键天然含目录维度，数据模型已留扩展位，后续迭代
- 30% 阈值自动切换：被手动选 + 涌现兜底取代
- 学生删题面头部的防篡改（删头 → 退化为单桶模式，可用但无任务粒度）

## 3. 题面格式契约（教师侧）

在现有题面管道（`# ===== 代码区 =====` 分隔线前注释 = 题面）上扩展：

```python
# 练习：L21 导入方式（week-05）
# [任务一] 使用模块导入并调用 filter_records 筛选 P03
# [任务二] 使用函数导入并直接调用 filter_records
# [任务三] 同名冲突与别名调用
# ===== 代码区 =====
<学生可见的初始代码>
```

解析规则（服务端，评审请求 code 入口统一解析）：

- 分隔线前每行 `#` 注释：首行非空 = 标题（沿用现有 extractExerciseTitle 清洗：去"练习："前缀与括号备注）
- `[任务X]` 前缀行（`[...]` 内文案宽容，任务一/T1 均可）= 任务声明，**按出现顺序**成清单，任务名 = `]` 后文字
- **任务声明 ≥2 才视为多任务题**；0/1 个声明 = 单任务题，行为与现状完全一致（单任务声明只当普通注释）
- 学生端零改动：头部随教师 push 下发、随学生文件保留、随评审请求上送

## 4. 评审协议：逐任务结论

- 评审 prompt 注入权威任务清单 + 判定规则：**逐任务独立判定；代码只写了任务一 → 任务一 pass、二三 unreviewed（未动=初始态）；禁止因整文件不完整而全部判 fail**
- LLM 返回 `tasks: [{name, status: pass|fail|unreviewed, reason}]`；任务名与声明清单宽松匹配（包含式）；解析失败/缺任务 → 回退"所有任务同一结论"（与现状等价，不丢评审）
- 学生回执（服务端拼接，学生端 UI 零改动）：
  - 整体 status：任一任务 fail → fail；全部 pass → pass；否则 unreviewed
  - reason：`✅任务一 / ❌任务二：<原因> / ⬜任务三：未开始` 拼接
- 教师端状态注入沿用文件级：有 fail 任务 → 注入 review_fail（rawMessage 为失败任务原因汇总）；全 pass → 置绿；否则 unreviewed 路径不变

## 5. 数据模型与进度桶

- `review_results` 表新增 `task_id` 列（TEXT NULL；NULL = 存量单任务行/整文件行）；SQLite `ALTER TABLE ADD COLUMN` 无破坏迁移，重启回放兼容
- **多任务题：每个任务一行评审结果**（filePath + taskId 定位）
- 进度桶 key：内部 `filePath::任务名`；多任务题每任务一个桶（passed/stuck/unreviewed），随文件级 item 的 `tasks[]` 数组下发
- 文件级 top-level 三态汇总（多任务题）：按学生聚合——全部任务 pass → passed；任一任务 fail → stuck；其余 → unreviewed（供非水桶场景的旧消费方兜底）
- **run 事件语义修正（关键）**：
  - run 是文件级信号。多任务题 run 失败**不判任何任务 fail**（否则一个分号错误打红全部任务），仅推进涌现时间
  - 单任务题 run 失败维持现状（latest=fail）
  - runOk 弱信号 / degraded 降级：应用到该文件全部任务桶（LLM 挂掉时桶不被卡死）
- 任务状态唯一权威源 = 逐任务 LLM 评审

## 6. 大屏：文件下拉 + 任务 tab

- 完成度卡两级切换：
  - **文件下拉**（卡顶部）：选项 = **预选清单（管理页提前选定，置顶一组）∪ 当天涌现题（追加一组）**；默认"自动跟随"（现有涌现优先规则：有评审牵引优先 → 涌现时间最新）；教师点选某文件 = 锁定，不再自动漂移；可选回"自动跟随"
  - **任务 tab**：选中文件的任务声明 ≥2 时显示（任务一/二/三），默认选中第一个未全员通过的桶，教师点击切换；单任务/无声明 = 无 tab、单桶现状
- 涌现判定与延迟：文件当天收到任一学生 run/评审事件即涌现（秒级）；涌现仅影响下拉清单的追加，焦点切换只由教师点选驱动
- 预选但尚未涌现的文件可点选：无桶数据时水桶区显示"尚未有学生运行"占位

## 7. 服务端接口与管理页

- **管理页新增「本节课文件」面板**（2026-11-09 用户追加拍板，推翻"零新增接口"初版决定）：教师按节奏讲课时"等第一个学生 F5"的涌现延迟是常态，需要提前锁定未涌现的题
  - `GET /api/exercises/tree`：服务端走 Gitea API 列题库 main 分支目录树（一级目录 = 作业文件夹 → 文件夹内 .py 文件），带短缓存（60s）
  - `GET /api/classroom/lesson-files` / `POST /api/classroom/lesson-files`：预选清单读写，存 meta 表（重启保留、换教师机不丢）
  - 管理页面板：文件夹下拉 → 文件多选（勾选）→ 保存
- 大屏下拉合并语义：预选清单 ∪ 涌现清单，分组展示（预选置顶 / 涌现追加），涌现的文件"有就不动、没有就添加"
- 预留：题库文件树接口已覆盖"提前锁定"诉求，无需额外扩展

## 9. 测试要点

- 题头解析：多任务/单任务声明/无声明/学生删头/`[任务X]` 宽容匹配
- 进度桶：任务二 fail 不动任务一 pass；文件级三态聚合；run 失败在多任务/单任务下的不同语义；runOk 降级到全部任务桶
- 评审：逐任务解析、任务名宽松匹配、解析失败回退、学生回执拼接、注入事件
